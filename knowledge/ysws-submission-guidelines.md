# YSWS Project Submission Guidelines: AI Policy

## AI Usage Rules and 30% Limit
At most, your project may only be built by AI up to 30% of the total code. AI code is limited to a hard ceiling of 30%. You can use AI tools (such as ChatGPT, Claude, or GitHub Copilot) for quick lookups, syntax assistance, debugging, learning, and scaffolding boilerplate code, but AI cannot make 40% or most of your project. Submitting a fully AI-generated project is strictly prohibited. If you only used AI for some debugging or syntax, that is completely fine as long as it is well within the 30% limit and disclosed.

Your project's README cannot be built by AI. You must write your own README by yourself.

## Disclosing AI Usage
You must disclose where and how AI was used in your project submission notes and README. Reviewers determine and verify the AI percentage by examining the self-reported AI disclosure notes and cross-referencing them against the GitHub commit history, commit cadence, and code structure.

## Consequences of Exceeding the AI Limit or Hiding AI
If you exceed the 30% AI limit, reviewers will reject your project or reduce/deflate your payout and approved hours.
If you hide or do not disclose your AI usage, your project will be rejected and your payout penalized. Hiding AI usage is treated as dishonesty and fraud, which can lead to disciplinary action or a permanent ban from Hack Club programs.

## Hardware and Firmware AI Rules
The 30% AI rule does not apply to hardware design. For hardware projects, all CAD assemblies, 3D models (.step files), and PCB designs/schematics must be 100% original, custom designs by you — not generated by AI, and not copies of tutorials. AI cannot generate your CAD. Submitting fully AI-generated design files will result in rejection and may lead to a permanent ban.
For firmware (microcontroller code), AI is permitted only under the standard software code limit of up to 30% with honest disclosure, but AI cannot generate your entire firmware.

## Software Project Requirements and README
For software projects, your repository must contain a README explaining what the project is, how to set it up or run it, and how it can be experienced. It should clearly document what technology went into making it. Software projects must have public open-source code on GitHub and a working playable URL. Software projects do not require PCB schematics, wiring diagrams, or CAD files.

## Hardware Project Requirements
For hardware projects, the repository must contain everything someone would need to build the project from scratch. This means, at minimum:
* PCB schematics and wiring diagrams
* CAD files in a modifiable format (.STEP, .blend)
* A bill of materials (BOM) with specific part names
* A README with assembly and soldering instructions

## Returned Submissions and Resubmissions
A returned submission (or "Needs Changes" verdict) is not a penalty, fine, or final rejection. If a submission is returned, the reviewer provides specific feedback explaining what needs to be changed. You can make the requested adjustments and resubmit your project for review. Resubmitting an updated project after addressing feedback makes it eligible for approval.

## Referral Codes and Expiration
Referral codes expire in 48 hours (2 days) after being generated. Submitter referral links and codes must be redeemed within the 48-hour expiration window before they become invalid.
