What pixie does today

Answers from your docs grounded

Each reply is grounded in the bot's own corpus. The answer comes with a citation, and the model is told to admit ignorance rather than invent a fact about a specific program.

One image, many programs fleet

Identity, commands, channels, sources and dates all come from PIXIE_PROGRAMS_JSON. A single engine image runs Pixl, Solvable, Twisted, and any future YSWS without code changes.

Twelve commands, all slugged new

Set PIXIE_BOT_SLUG=sol and the bot becomes /sol, /sol-teach, /sol-gaps, all twelve commands. The manifest is generated from the same slug, so the app and listeners cannot drift.

Inline FAQ support new

Sources can carry their content inline rather than as a fetched URL. A typed-in FAQ rides in PIXIE_PROGRAMS_JSON, so a fleet bot needs no file in the image to know what to answer.

Teachable, but approval-gated

/sol-teach adds a candidate. /sol-pending and the Home tab queue review it. Nothing enters the corpus unapproved.

Docs gaps with an honest signal new

Ranked by distinct askers, not raw ask count. Trolling doesn't outrank real questions anymore. Maintainer-rejected questions stay out.

Weekly report + captured answers

Monday-morning post to the help channel with what's outstanding. Classifies gaps into docs, transient, and noise so the report's "to-do list" actually is one.

Program dates answer directly

"When is it out", "when does it close", "how long until launch" — the corpus section rebuilds on every refresh, so dates that have passed say so instead of reciting something stale.

The before / after on doc gaps

The single most user-visible bug fix this round. A maintainer was seeing "add this to the docs" for questions that were obviously trolling or noise, and a single asker spamming the same question could outrank eight real people.

Before

One asker, eight times:

does pixie have a boyfriend — ranked #1 with 8×

Eight different people, once each:

how do i submit my project — ranked #2 with 8×

The loud single asker wins. Maintainers get a to-do list full of noise.

After

One asker, eight times — hidden by the asker-count floor

Eight different people, once each — ranked #1 with 8 askers

Judge prompt now rejects as noise: flirty/banter, memes, "say something funny", "can you do my homework", "are you a real person".

Maintainer drops a draft → that question is excluded from the auto-ranked list for the same window the rank itself covers. The same trolling beat can't keep coming back.

Recent changes, in code

  • lib/db.js — new gap_rejections table ops (recordGapRejection, clearGapRejection). topGaps now counts distinct askers, requires at least 2 for the user-facing surface, normalizes question text on insert, and excludes rejected questions.
  • lib/schema.js — migration row creating gap_rejections. The migration loop now handles CREATE TABLE migrations as well as the existing ALTER TABLE shape.
  • lib/report.js — the gap judgement prompt is rewritten with explicit rules against pure noise (flirty/banter/meme/human-required) and a longer set of live examples. draftGaps and the weekly report use minAskers: 1 since they go through human review.
  • lib/home.js — the home tab's Drop button now records a gap rejection. The drop was a UI gesture with no data effect before.
  • lib/programs.js — PIXIE_PROGRAMS_JSON loader ahead of the file loaders. shared() gated on the same variable so fleet bots stop inheriting Pixl's quick links.
  • lib/knowledge.js — fetchSourceText handles inline content alongside file:// URLs. loadSources stopped requiring a url, which had been silently dropping every inline source.
  • lib/brand.js — new module: name(), slug(), cmd(), id() read from PIXIE_BOT_NAME/PIXIE_BOT_SLUG per call, not at require time. The unprefixed /guide alias only registers for the default bot since command names are unique per workspace and every fleet bot shares one.
  • lib/commands.js — every literal /pixie-* string replaced with brand.cmd(...). Same shape in help text, the welcomeText string, and the rebuilt teachThread shortcut id.
  • lib/home.js, lib/identity.js, lib/respond.js, lib/report.js — user-facing copy now reads names and commands from brand, not literals. The gap judgement prompt, the weekly report, the app home header, and the bot's own identity block all match the deployment's name and command set. Two Pixl-specific claims (Ricky, Pixorpheus) are dropped for rebranded bots rather than reproduced under a different name.
  • scripts/manifest.js — new. bun run manifest prints the Slack app manifest for whatever PIXIE_BOT_SLUG is set, with scopes, events, commands and the socket-mode toggle ready to paste into api.slack.com/apps.
  • .env.example — new. The engine never had one. Now exists.
  • SELF-HOST.md — new. Fork, manifest, configure, deploy. About 20 minutes per the actual steps.
  • lib/manifest.test.js — asserts the manifest and the engine register exactly the same set of commands. Drift produces a command that appears in autocomplete and silently does nothing.
  • lib/db.test.js — five new tests on gap ranking and rejection. Cover the actual fixes: a single asker is not a gap, asker count outranks ask count, rejection hides the question, clearing the rejection brings it back, normalization keys on lowercase + whitespace.
  • pixie-wizard/supabase/migrations/001_fleet_config.sql — new. bot_slug (unique), program-shaped columns, behaviour knobs, extra credential slots, volume id, pool account provenance, drops the one-live-trial-per-requester index that was right for a trial programme and wrong for a fleet.
  • pixie-wizard/lib/generateConfig.ts — renderProgramsJson + DB_PATH + multi-key pool + dead PIXIE_ANSWER_FALLBACK_BASE_URL removed. SLASH_COMMANDS refactored to a suffix list so the manifest and listeners cannot disagree.
  • pixie-wizard/lib/railway.ts — createVolume added. Always sends environmentId even though VolumeCreateInput doesn't mark it required (without it the mutation reports success while attaching the volume to nothing).
  • pixie-wizard/lib/provisionTrial.ts — volume is created before the first deploy since the engine opens SQLite on boot.
  • pixie-wizard/scripts/add-pool-account.ts — new. Adds a Railway account to the pool with proper encryption (the one step the table editor can't do safely).

What's still outstanding

From the plan's §9 Order of work, the items still on the list:

  • Wizard form steps for behaviour (posture, scope, guides, tickets, escalation emoji) and admins beyond the requester — the columns and the env contract are in place, the form UI is the missing piece.
  • pixie fleet status (walk the pool × bots, report anything not SUCCESS) and pixie fleet check-account (provision and delete a throwaway project, proving the account's GitHub connection before a real user hits it).
  • Running the migration against Supabase, diffing the generated Slack manifest against a real Slack export, and turning on branch protection so the new CI workflow actually gates main rather than merely reporting on it.
  • The second Railway pool account, sourced legitimately. The build is identical; only the sourcing of accounts differs, and that's what determines whether the fleet is still there next month.
  • Before making the repo public: pixie.db is committed (with user IDs and questions from #pixl-help), claudepixie.txt contains real xoxb-/xapp- tokens, node_modules is in the repo, and there's no LICENSE. Recommend a fresh public repo from the current tree, not a forced-push of this one.
