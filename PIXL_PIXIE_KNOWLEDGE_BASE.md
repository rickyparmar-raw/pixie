# 3. What Pixl is

Pixl is a Hack Club YSWS where participants:
1. build real software or hardware
2. track/document their work
3. ship projects
4. have them reviewed
5. earn Restoration Energy and pixels from approved work
6. redeem rewards through the Pixl shop

Pixl has NPCs/trials and a game/story layer, but **trials are optional**. Participants may build their **own original project ideas**.

Pixl supports a broad range of projects, including websites, games, CLI tools, Python/C++ apps, Godot/Unity/GameMaker/Ren'Py projects, Roblox projects, PCBs, CAD, embedded systems, firmware, and custom electronics.

# 4. Eligibility

Current official rules:
- participant must be **18 or under when they ship**
- if they turn 19 while already in review, manual review should replace automatic rejection
- Hack Club account needs birthday and valid physical mailing address
- Pixl is global, but shop inventory differs by region

Current regions described by the docs include:
- United States
- North America
- South America
- Europe
- Asia
- India
- Africa

Hard exclusions include:
- school coursework assigned for a class grade
- work Hack Club has already funded or paid for

An old project is not automatically banned. Only genuinely new eligible work may be claimed.

---

# 5. School work

Do not blanket-approve school assignments.

If the work is assigned as coursework for a class grade, it is not eligible.

Personal work that happens to use skills learned in school may be different, but borderline cases should be escalated rather than loophole-lawyered.

---

# 6. Old projects, migration, and double dipping

Core rule: **the same work cannot be rewarded twice.**

If a project has history in Macondo, Forge, Stardance, another YSWS, a Hack Club grant, or paid Hack Club work:
- do not re-claim previously rewarded work
- clearly separate new work from old work
- only claim genuinely new eligible hours
- if another program's approval/reward status is unresolved, do not promise eligibility

A previously existing project can potentially continue in Pixl if the newly claimed work is genuinely new and independently eligible.

Trials are optional guided/featured builds.

Participants do **not** have to complete every trial before making their own project.

Trial content is dynamic. Use the live Pixl site for:

# 9. Restoration Energy (RE)

RE is permanent progression. **It is not spent when buying rewards.**

Current official tier rates:

| Tier | Name | RE per approved hour |
|---|---|---:|
| T1 | Spark | 12.5 |
| T2 | Signal | 15 |
| T3 | Grid | 18.75 |
| T4 | Nexus | 25 |

Tier depends on ambition, technical depth, execution, and project scope. Do not assign a tier confidently from a vague one-line description.

---

# 10. Hourly payout

Current official docs:
- starting rate: **$4/hour**
- maximum rate: **$6/hour**
- every **1,875 lifetime RE** adds **$1/hour**
- maximum reached at **3,750 RE**

Current milestones shown by the docs:

| Lifetime RE | Rate |
|---:|---:|
| 0 | $4.00/hr |
| 625 | $4.33/hr |
| 1,250 | $4.67/hr |
| 1,875 | $5.00/hr |
| 2,500 | $5.33/hr |
| 3,125 | $5.67/hr |
| 3,750 | $6.00/hr |

Current docs describe this as approximately **57 px/hr to 86 px/hr**.

Older support chatter mentioning a $3 starting rate is stale against current docs.

# 11. Levels

Levels are a progression display based on lifetime RE, not the direct payment formula.

Current docs describe:
- levels 1–10: 10 RE/level
- levels 11–50: 35 RE/level
- levels 51–100: 70 RE/level

# 12. "How many pixels is $1?"

Do not claim one universal shop conversion.

There are two separate concepts:
1. how approved hours earn pixels
2. how shop items are priced in pixels

The earning rate is defined by current payout/RE rules. Shop prices are dynamic and can reflect regional/current sourcing.

For exact current item price, use the live shop.

---

# 13. Collaboration

Team projects are allowed.

Current official collaboration rules:
- invite collaborators through the Pixl flow
- each person tracks their own time
- payouts are calculated independently per collaborator
- RE is calculated independently per collaborator
- there is no single shared team payout pool
- every collaborator must show real contribution

Adding a zero-work collaborator just to gain rewards can be treated as fraud and can jeopardize the submission.

Useful evidence includes commits, Hackatime, journals, and concrete contributions.

# 14. Software time tracking

Hackatime is the primary automatic tracker for software/coding work.

Typical flow:
1. install/configure Hackatime in the IDE/editor
2. work in the project
3. confirm the correct Hackatime project is recording
4. connect it to Pixl
5. journal/document the work
6. ship

**Current official software docs say only qualifying Hackatime hours after July 18, 2026 count.**

Older help-channel chatter sometimes mentions August 18. Current official docs win unless a newer organizer statement explicitly supersedes them.

---

# 15. Journals

Current software shipping guidance expects roughly **100 characters per logged hour**, with an absolute floor of 100 characters.

A useful journal should describe actual work:
- what changed
- what was attempted
- problems encountered
- decisions made
- progress/evidence

Do not encourage filler or fabricated retroactive journals.

---

# 16. Avoid double counting

The same real-world hour should not become two paid hours merely because it appears in two evidence systems.

Example:
- Hackatime tracks a coding hour
- journal documents that same hour

That does not make it two hours.

Likewise, Lapse can prove a build session while a journal explains it.

If the site UI appears to double-count, treat it as a possible bug instead of telling users to exploit it.

---

# 17. Hardware tracking

Current hardware docs emphasize:
- Lapse during the physical building phase
- journals
- progress photos
- source/design files
- finished-build photos
- demo video

If a physical build is not lapsed, time can be deflated due to weaker evidence.

Do not promise that journaling alone always replaces all other hardware evidence.

# 18. Research and learning time

Project-relevant learning/research can matter when credibly documented, such as:
- learning an API needed for the build
- reading technical docs
- researching formulas needed for implementation

Do not imply unlimited unrelated study time automatically counts.

# 19. Software ship requirements

Current official software requirements include:
- **public GitHub repo**
- README
- multiple commits showing progress
- working demo
- thumbnail
- eligibility confirmation
- honest AI disclosure

### Public repo
Current Pixl software docs explicitly call for a public GitHub repository.

Do not say a private repo is automatically fine if a reviewer can access it.

### README
README should explain:
- what the project is
- why it exists
- technology used
- setup/run instructions
- useful screenshots/visuals

### Commits
Use multiple meaningful commits showing real development. There is no rule requiring exactly one commit per hour, but one giant final commit is weak evidence for a large project.

# 20. Demo requirements

Software projects need a meaningful working demonstration.

Depending on the project, that may be:
- hosted site
- playable build
- downloadable release
- video demo
- other appropriate run/test path

A GitHub repo alone is not a demo.

CLI/self-hosted/specialized software does not need to pretend to be a browser game; use an appropriate demonstration method.

# 21. Hardware design requirements

Current official hardware design guidance expects:
- good README
- completed design
- original/custom work
- complete CAD assembly when relevant
- real attachment/mounting method
- firmware when relevant
- sanity-checking
- supporting project files

Repository should include relevant files such as:
- BOM CSV
- links and total cost
- PCB source files when applicable
- `.step` plus source CAD file or Onshape link
- firmware source
- other required project files

The BOM should include already-owned parts too.

# 22. Physical hardware build

For physical builds:
- Lapse the building phase where expected
- journal the work
- take progress photos
- include finished-build photos
- include a demo video in README
- update design/source files if the actual build required changes

# 23. CAD-only / design-stage hardware

CAD is legitimate project work.

A hardware design submission can be meaningful without a finished physical unit if it satisfies the current design requirements, including complete assembly/source files/BOM and firmware where applicable.

Do not reject CAD merely because a physical device is not yet built. Do not accept a half-finished model as a complete design either.

---

# 24. Firmware without physical hardware

Current hardware guidance says firmware should be included when applicable even if it has not yet been tested on real hardware.

Participants should clearly distinguish:
- tested behavior
- simulated behavior
- unverified behavior

Never tell them to fake a hardware test.

---

# 25. Originality and plagiarism

Pixl rewards genuine building.

Current hardware docs are especially strict about:
- plagiarism
- stolen design files
- fully AI-generated design files presented as the participant's own work

These can lead to permanent rejection or bans.

Tutorials can be useful for learning, but a direct tutorial copy without meaningful original contribution may fail originality/depth expectations.

---

# 26. AI use

Current Pixl policy allows AI tools, but AI use must be **honestly disclosed**.

Core answer:
- AI assistance is allowed
- disclose it honestly
- participant still needs genuine work and understanding
- AI cannot be used to fake hours/evidence
- fully AI-generated or stolen work presented as personal work can be rejected

Do **not** invent a numeric AI percentage unless a current official Pixl source explicitly gives one.

For hardware, fully AI-generated design files presented as personal work are specifically unacceptable.

AI used to explain/debug/teach is different from AI replacing the participant.

---

# 27. Returned projects / resubmission

Returned projects can be fixed and resubmitted.

If a reviewer requests changes:
1. make the changes
2. update repo/demo/evidence
3. resubmit through the Pixl flow

A request for changes is not automatically a permanent rejection.

# 43. Deflation

Reviewers may approve fewer hours than claimed when evidence/scope does not support the claim.

Deflation can happen because:
- weak evidence
- missing proof
- excessive claimed time relative to work
- suspicious/inflated tracking

Deflation is not automatically a fraud accusation.

# 48. Current quick FAQ

### What is Pixl?
A Hack Club YSWS where you build and ship software/hardware, document your work, get reviewed, earn RE/pixels, and redeem rewards.

### Do I have to do trials?
No. Trials are optional.

### Can I make my own project?
Yes, if it meets Pixl's rules.

### Who is eligible?
You must be 18 or under when you ship and have required account/address info.

### Can I collaborate?
Yes. Everyone tracks and earns from their own genuine work.

### Does RE get spent?
No.

### What are tier RE rates?
- T1: 12.5 RE/hr
- T2: 15 RE/hr
- T3: 18.75 RE/hr
- T4: 25 RE/hr

### What is the current hourly rate?
Current docs say $4/hr to $6/hr depending on lifetime RE.

### Does software need a public repo?
Yes, current docs require a public GitHub repo.

### Do I need a README?
Yes.

### Do I need a demo?
Yes, an appropriate working demonstration.

### Do I need to commit every hour?
No exact hourly commit rule. Use multiple meaningful commits showing progress.

### Is AI allowed?
AI assistance is allowed if honestly disclosed, but genuine participant work/evidence is still required.

### Can I fix and resubmit a returned project?
Yes.

### How long do reviews take?
No guaranteed SLA. Current guidance says days to even around two weeks can happen.

### Should I ping reviewers?
No. Current team guidance discourages repeated reviewer pings/priority requests.

### When does Pixl end?
As of 2026-09-12, no official end date is announced.

### Are shop prices permanent?
No. Use the live shop.

### Are orders locally sourced?
Pixl generally tries to source locally where practical; it is not a guarantee for every order.

### Are customs always covered?
Do not assume that.
